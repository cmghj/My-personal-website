# Supabase 结构文件

这里保留两个正式迁移文件：

- `202609160001_initial_archive.sql`：全新项目一次性创建最终结构。
- `202609170001_finalize_archive.sql`：旧结构一次性升级到最终结构的历史记录。

## 当前项目状态

当前线上 Supabase 已于 2026-09-17 成功执行最终升级。不要再次运行这两个文件，也不需要继续操作 SQL Editor。

保留迁移文件是为了让数据库结构可追溯：以后查看代码时能知道数据库最初如何建立、旧数据如何安全转换。它们不会被网页运行，也不会增加网站体积。

如果以后面对另一个仍使用旧结构的 Supabase 项目，才需要先从 Storage 页面删除空的 `private-media` bucket，然后在 SQL Editor 中运行一次 `202609170001_finalize_archive.sql`。Supabase 不允许通过 SQL 直接删除 Storage bucket。

升级脚本会保留文章、标签、媒体、网站设置和既有历史版本，同时：

- 删除空的 `albums`、`album_media` 预留表；
- 删除未使用的 `private-media` 存储桶；
- 将媒体 `visibility` 改为语义准确的 `purpose`；
- 删除没有被产品使用的媒体预留字段；
- 把网站设置整理成一行三个明确字段；
- 把旧历史版本迁移到可完整恢复的快照结构。

安全保护：如果 `private-media` 内意外存在文件，或者还没有通过 Storage 页面删除，升级会直接中止并回滚。处理完成后重新运行完整脚本即可，不会出现只升级一半的状态。
